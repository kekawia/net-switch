## 2. Why BPF map helpers cannot recursively transmit a packet, and how nested interrupt terminals are fenced

1. **No recursive packet transmit from BPF helpers:** `capture`, `consume`, and `freed` invoke only `bpf_map_lookup_elem`, `bpf_map_update_elem`, `bpf_map_delete_elem`, `bpf_get_smp_processor_id`, `bpf_get_current_pid_tgid`, `bpf_get_current_task`, and `bpf_probe_read_kernel` (plus `bpf_ktime_get_ns` in fault builds). All maps (`packets`, `readers`, `read_slots`, `config`, `health`, `cpu_state`, `faults`) are preallocated (`BPF_F_NO_PREALLOC` is never set). None of these helpers enters the networking stack or transmits an `sk_buff`.
2. **Same-CPU softirq / interrupt terminal during an armed read:** While a registered reader thread is executing `read(tun_fd)` with its slot `control.armed == 1`, a softirq (such as a `netem` timer or NET_RX/NET_TX softirq) can interrupt that same task on that CPU and free or consume a packet belonging to the selected TUN device. Because `bpf_get_current_pid_tgid()` still returns the interrupted reader task's `tgid`/`tid`, `terminal()` matches the reader's registration and armed slot.
3. **Why nested terminals cannot corrupt provenance:**
   - In `terminal()` (`internal/engine/linux/ownerbpf/bpf/bridge.c`), `__sync_fetch_and_add(&s->completion.count, 1)` executes **before** stamping or writing `s->completion` / `s->packet`.
   - If the reader's own `consume_skb` and a nested softirq `kfree_skb` (or `consume_skb`) both execute while the slot is armed, `s->completion.count` becomes `>= 2`.
   - If only a nested `kfree_skb` executes (for example on `EFAULT` or if the reader's own `consume_skb` was skipped), `s->completion.terminal` is `NS_TERMINAL_FREE` (`2`) rather than `NS_TERMINAL_CONSUME` (`1`).
   - `CheckRead` (`internal/engine/linux/ownerbpf/provenance.go`) strictly requires `s.Completion.Count == 1 && s.Completion.Terminal == TerminalConsume`. Any `Count > 1` or `Terminal == TerminalFree` on a positive read returns `ReadAmbiguous` with an empty `PacketRecord{}`, refusing attribution rather than guessing.
   - If the nested softirq interrupted the reader **inside** `consume` or `freed` on a kernel with the v6.1+ per-program recursion guard (`__bpf_prog_enter_recur`), the inner callback is suppressed by the kernel and increments that program's `recursion_misses` counter. The reader's post-burst full memory barrier and three `BPF_OBJ_GET_INFO_BY_FD` counter samples detect the delta before any packet in the burst is released, refusing the entire burst with `ReadRecursion` (`attribution_unknown_recursion`) and `Rebuild: true`.
