# M4: native goldens for the frozen Windows fixture inputs

2026-10-25. Based on main `cbc1426c` (PR #99 merged) and the retirement plan's
"Independent golden replacement" section, with locked design §§4.1, 4.6, 5.4 and
5.11. This adds evidence only. `test/fixtures/windows-golden.json`, its hashes,
`TestFrozenWindowsGoldenHashes`, the sing-box adapter and every existing test
stay unchanged, and nothing here touches the live-update runtime under review
in PR #103. The native semantic replay of the 25 traces is separate work.

## What the old fixture holds

The frozen file hashes sing-box output for one fixed input family: lines `aa`
(Ethernet), `bb` (Wi-Fi) and `cc` (Phone); pins `C:\Apps\app-1.2.3\Browser.exe`
→ aa, `C:\Games\game.exe` → bb and
`C:\Program Files\WindowsApps\Example_1.2.3_x64__publisher\App.exe` → cc; shares
1, then 0.6/0.4, then 0.5/0.3/0.2. From it:

- 12 engine-config hashes: 1, 2 or 3 lines × TUN or proxy inbound × IPv6 on/off;
- 6 rule-set hash maps: 1, 2 or 3 lines × pinned or combined, each with the
  **last** line in the blocked set;
- 1 empty-apps rule-set map.

## New tests

Pure, literal, no engine, TUN, service or network. Every expected configuration,
identity and decision is written out by hand; none is generated by the compiler
or selector being tested. The revision hash is checked against the hash of the
literal configuration, so it binds the literal, not the output.

| File | Tests | Cases |
| --- | --- | --- |
| `internal/control/engine/native_golden_test.go` | `TestLegacyRuleFamiliesCompileToLiteralNativePolicy` (10 subtests), `TestLegacyOneLineBlockedMainIsRejectedNatively`, `TestLegacyWindowsPinIdentities`, `TestLegacyUnknownLinesAndInvalidRevisions`, `TestLegacyLaneRedirection`, `TestLegacyIPv6Families`, `TestLegacyEmptyAppsReplacesPinsWithoutASentinel` | raw fixture inputs through the production `NativeRevision` compiler with Windows identity rules, then `policy.Compile`, `Decide` and `Predict`; two cases also drive the real in-memory `flows.Table` |
| `internal/control/native_golden_control_test.go` | `TestLegacyGoldenInputsAsControlProducesThem` (14 subtests) | the same lines, pins and weights as Control's own policy assembly produces them (health, caps, strict, IPv6 setting and adapters are explicit inputs), then the same compiler and selector |

Each decision row covers the browser (pinned aa), the game (pinned bb), the
store app (pinned cc), an unpinned known owner and an unknown owner, at source
port 40000 with sequence position k = 1, plus: the same owners over IPv6, the
unknown owner at ports 1023 and 1024, the game at port 80, the unknown owner's
decisions for k = 1..10, and the predictions for the unknown owner and the game.
Every decision carries the literal revision number.

Run locally with the pinned toolchain at Idle priority:

```
go test -mod=vendor -p 2 -count=1 -run TestLegacy ./internal/control/engine ./internal/control
```

Hosted, these run inside the ordinary `go test ./internal/...` legs of `ci.yml`.

Control row "3 lines, empty apps" saves an empty pin set over the three pins. | No sentinel identity exists natively. |
| unblocked companions (not in the old fixture) | — | "1 line pinned/combined", "2 lines pinned/combined, open" (60:40: `bb aa bb aa aa bb aa bb aa aa`), "3 lines pinned/combined, open" (50:30:20: `bb aa cc aa aa bb aa cc bb aa`); Control "healthy" rows with weights 3:2 and 5:3:2 | — |

Share mechanism: the old `share-*` files listed ports 1024–65535 by golden-ratio
hashing of the **port**; the native selector hashes the admitted-flow counter
**k** (§5.4). The literal 10-flow sequences above are the replacement. The
10/50/300-flow evenness check stays `policy.TestEvenness`, and "prediction and
rejection do not consume a sequence position; a UDP admission consumes one"
stays `flows.TestRejectedAndPredictDoNotAdvance`; neither is duplicated.

Also covered by the new literal cases: source ports below 1024 stay on the
main lane while 1024 is shared; a pin and a block both beat the low-port rule;
lanes default to themselves and a redirected lane keeps its name in the
decision while the physical line and the share slices follow the target
(`TestLegacyLaneRedirection`); pins, shares, lanes and blocks naming an unknown
line drop out; revision 0 and a line without an interface alias are refused.

### Windows identity (`TestLegacyWindowsPinIdentities`)

The three pins compile to `c:\apps\app-*\browser.exe`, `c:\games\game.exe` and
`c:\program files\windowsapps\example_*_x64__publisher\app.exe`. The test
asserts that the production Windows owner key gives the same literal identity
for the pinned path, another version (`app-2.0.0`, `Example_2.0.1.0_x64__…`) and
other casing, and a different literal for each near neighbour
(`app-1.2.3-beta`, no version folder, drive `D:`, `Browser-helper.exe`,
`game2.exe`, `Mods\game.exe`, `_arm64__`, another publisher, `Helper.exe` in the
store folder). Matches route to the pinned line; neighbours stay on the main
line. Two saved pins for the same program at different versions: the later
saved entry wins, in either order.
